### Run a model

```
ollama run gemma4
```

### Launch integrations

```
ollama launch
```

Configure and launch external applications to use Ollama models. This provides an interactive way to set up and start integrations with supported apps.

#### Supported integrations

- **OpenCode** - Open-source coding assistant
- **Claude Code** - Anthropic's agentic coding tool
- **Codex** - OpenAI's coding assistant
- **VS Code** - Microsoft's IDE with built-in AI chat
- **Droid** - Factory's AI coding agent

#### Examples

Launch an integration interactively:

```
ollama launch
```

Launch a specific integration:

```
ollama launch claude
```

Launch with a specific model:

```
ollama launch claude --model qwen3.5
```

Configure without launching:

```
ollama launch droid --config
```

#### Multiline input

```

... world!
... """
I'm a basic program that prints the famous "Hello, world!" message to the console.
```

### Inspect a registered GGUF model

Ocelot can inspect local GGUF models registered with `ocelot add`:

```
ocelot info gemma2b
ocelot info bge-small --json
```

### Quantize a GGUF model

Ocelot can run the installed `llama-quantize` engine and optionally register the output model:

```
ocelot quantize input.gguf output.gguf --type q4_k_m
ocelot quantize input.gguf output.gguf --type tq2_0 --threads 8 --imatrix importance.dat --register
```

Add `--allow-requantize` to requantize a model that is already quantized (for example, going from `tq3_1s` to `tq1_0`). This can reduce quality; only use it when the source is already a quantized GGUF and a smaller target is required:

```
ocelot quantize input.gguf output.gguf --type tq1_0 --allow-requantize
```

### Inspect the local Ocelot engine

Ocelot can report the installed puma.cpp engine version, Metal device, supported quant types, GGML backends, and installed runtime files:

```
ocelot engine info
ocelot engine info --json
```

### Sync Ocelot models to LLM Dynamix

Ocelot can keep LLM Dynamix configured with a local mirror of registered Ocelot models.

The command writes to:

```
~/.llmdynamix/config.yaml
```

Use `register` to add models:

```
ocelot llmdynamix register gemma2b
ocelot llmdynamix register --all
```

Use `list` to compare local Ocelot registrations with what is already in the config:

```
ocelot llmdynamix list
```

Example output:

```text
Synced models:
  - gemma2b (ocelot) → chat
  - nomic-bert-embed (ocelot) → embedding
Unsynced models:
  - qwen2.5 (not in ~/.llmdynamix/config.yaml)
```

Use `unregister` to remove a model from the config:

```
ocelot llmdynamix unregister gemma2b
```

Details:
- Sync is idempotent: already-synced models are skipped.
- If a model is already present but its endpoint changed, the endpoint is updated.
- GGUF model type is inferred from metadata:
  - `bert` and `nomic-bert` archives are `embedding`
  - all other models are `chat`
- Synced entries are written as OpenAI-compatible models with:
  - `name` set to the registered model name
  - `alias` set to `<model-name> (ocelot)` so you can identify managed entries
  - `base-url` set to `http://127.0.0.1:12435/v1`

### Sign in to Ollama

```
ollama signin
```

### Sign out of Ollama

```
ollama signout
```

### Create a customized model

First, create a `Modelfile`

```
FROM gemma4
SYSTEM """You are a happy cat."""
```

Then run `ollama create`:

```
ollama create -f Modelfile
```
